# Creative Intent Script Skeleton

目标不是马上写完分镜，而是先用最少但准确的决策，把用户“想做什么视频”收敛成一条可拍摄、可生成、可复用原片片段的骨架。完整镜头脚本交给 `universal-ugc-video-script-generation`。

## 输入

优先使用已有上下文，只在缺口真正影响结果时追问：

- 新视频创作说明：商品、目标用户、卖点、发布市场、平台、期望时长和 CTA。
- 参考视频分析：Hook、价值段、CTA、镜头节奏、口播、字幕、音乐和可复用片段。
- 商品事实：真实功能、规格、可展示证据和不能出现的宣称。
- 制作边界：必须复用的原片时间段、必须全新生成的片段、人物/场景限制、画幅和交付格式。

把“用户明确说明”“视觉证据支持的判断”“为推进创作所做的假设”分开记录。不得把推断包装成商品事实。

## 使用参考库

先使用 `$video-references` 并读取其 `SKILL.md`，再按其中的“意图与骨架阶段”检索：

1. 根据商品功能、视觉证据和叙事机制，选 3 篇同品类候选和 1 篇跨品类候选。
2. 每篇只读取首行骨架和第二个 `---` 之前的注意项。
3. 记录真实文件路径、可借鉴机制和不能照搬的边界。
4. 如果品类不足，明确说明使用了哪些跨品类结构。

参考库用于启发，不是答案库。不能因为某个参考脚本有高冲突或夸张动作，就强行加入不符合当前商品事实的桥段。

## 意图决策

在写骨架前，先完成下面六个判断：

| 维度 | 要回答的问题 |
| --- | --- |
| 目标 | 用户看完后应该理解、相信或做什么？ |
| 受众 | 谁在什么情境下停留？具体痛点或欲望是什么？ |
| 承诺 | 视频用一个可感知结果给出的核心承诺是什么？ |
| 证据 | 哪些真实镜头、动作、对比或演示能够兑现承诺？ |
| 机制 | Hook 如何制造停留，中段如何升级，结尾如何闭环？ |
| 可行性 | 哪些片段复用原片，哪些需要生成或补拍，时间是否足够？ |

如有多个合理方向，最多给出 3 个概念路线，并用“需求匹配 × 视觉证明强度 × 制作可行性”选择主方案。不要只按参考脚本的相似度选择。

## 骨架要求

最终必须给出一条可直接传给内容填充阶段的一行骨架，格式为：

```text
1.[目标国家]，[建议时长]，[风格定位]；[从问题出现到结果兑现的一气呵成剧情与物理动作]
```

同时给出分段骨架：

| 段落 | 建议时间 | 叙事任务 | 核心动作/画面证据 | 来源策略 |
| --- | --- | --- | --- | --- |
| Hook | 例如 0-3s | 制造停留和结果预期 | 具体动作或冲突 | 复用/复刻/生成 |
| Value | 中间时间 | 逐层提供价值与证据 | 2-4 个逐级升级的点 | 复用/复刻/生成 |
| CTA | 结尾时间 | 完成收束和行动指引 | 与钩子呼应的定格或动作 | 复用/复刻/生成 |

来源策略必须使用以下一种：

- `reuse`：直接使用参考视频的指定原片时间段。
- `replicate`：复刻参考片段的动作或镜头关系，但替换为当前商品。
- `generate`：需要新生成，无可用原片证据。
- `hybrid`：原片与生成或补拍组合。

## 输出

按以下顺序输出，保持紧凑：

1. **需求理解**：一句话概括用户真正要完成的视频结果。
2. **关键事实与假设**：只列会改变脚本的内容。
3. **参考检索**：实际文件路径和各自借鉴的机制。
4. **方案决策**：主方案及选择理由；有备选时写明取舍。
5. **一行骨架**：使用上方固定格式。
6. **分段骨架**：给出 Hook、Value、CTA、时间和来源策略。
7. **待确认项**：只列确认后会改变镜头数量、事实表述或制作路线的点。

在用户确认骨架前，不要输出完整的 Lens 级分镜，也不要调用视频生成工具。

## 边界

- 不虚构商品功效、测试数据、人物身份或用户评价。
- 不照抄参考脚本的商品外观、演员设定和台词。
- 不为了视觉刺激加入危险、违法或平台高风险行为。
- 用户已明确时长、市场或音轨策略时，不擅自改变。
- 若原片分析缺少时间戳或证据，明确标记不确定性，不自行补造。
