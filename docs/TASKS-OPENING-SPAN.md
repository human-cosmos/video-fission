## 1. 目标

在现有理解、拆分、观察能力之上，增加「视频开头」区间的识别，并让脚本与成片把它当成一个连续块使用。

「开头」不是前几秒的 hook（开场钩子）。Hook 仍然是最前面那个抓住注意力的职责；开头是从 0 秒起到故事、画面、节奏告一段落的连续单元，一般约 10–15 秒，但以内容为准，禁止按 3 / 10 / 15 秒整点硬切。

最终的开头拆分**必须**来自多模态视觉模型的理解结果。模型输出是第一步，也是更重要的一步；本地只允许在模型结果之后做一次小范围吸附，不得用本地启发式覆盖模型的语义判断。提示词必须按第 4 节精心实现，不得只加一个空字段。

前端必须标出开头区间。脚本和成片必须把开头当成连续块：开头内部不得再切一刀或加转场/淡化，把 hook 段和开头里后面的内容拆成两段不连续的镜头。

## 2. 非目标

- 不把 hook 角色改成 10–15 秒，也不新增第四种 `role`。现有 `hook` / `value` / `cta` / `other` 与一级标签映射保持不变。
- 不推翻 `docs/TASKS-VIDEO-PIPELINE.md`、`docs/TASKS-CHAT-NATIVE-PRODUCTION.md`、`docs/TASKS-SLOT-UNDERSTANDING.md` 已锁定的阶段顺序、卡片稳定 id、无 Key 时管线必须跑完、`replace_policy` 和对话入口。
- 不把本地切点/静音启发式当作「最终开头」。无 Key 或模型失败时，管线仍须跑完，但不得把本地暂估伪装成模型开头。
- 不在吸附阶段把模型给出的开头结束点拉到窗口外的「更漂亮」切点，也不为了凑 10–15 秒而新增切片。
- 不删除硬 Agent 约束，不改参考库 630 篇脚本，不接入 OSS / GCloud / 素材库，不动 5173。
- 本轮不把有 Key 观察卡、三级标签的历史残留 UI 问题纳入范围，除非改动直接碰到。

## 3. 现状与为何要改

### 3.1 现有分解

`run_decompose`（`understand/service.py`）流程已经是：转场检测 → 本地 `plan_segments` 兜底 → 有 Key 时整片理解与切片 → `refine_segments` 吸附片段边界 → 切出片段 → 可选片段理解 / observe。

本地 `pipeline.plan_segments` 把 hook 定在 1.5–3 秒（时长 15%，上限 3000ms），再吸到附近静音或场景切点；附近没有切点时，会在这个时间点硬切。这正是「前几秒 hook」，会切断连贯开场。

远程提示词（`understand/prompts.py` 的 `prompt_video_split`）已要求：不按固定间隔机械切割；第一段通常是开场钩子、不超过 10 秒；整片标签已有 `opening_types` / `opening_forms`（开场风格分类）。这些都不是开头起止时间，模型目前也没有 `opening` 区间字段。

`refine_segments` 只把已有片段边界微调整到附近转场峰值，并不判断「开头故事在哪结束」。

### 3.2 现有脚本与成片

`local_script` 按片段逐条出镜：默认 hook / cta 生成、value 复用。若 hook 只有 2–3 秒、开头实际到 12 秒，成片会在开头故事中间切开，甚至一段生成、一段复用。`_stage_compose` 还会在镜头交界做 `apply_edge_fades`。这与「开头是连续块」冲突。

### 3.3 原则（锁定）

1. **模型优先**：开头区间是视觉理解的产物，不是时间窗口规则的产物。
2. **本地只吸附**：模型给出 `opening.end` 后，只在小窗口内吸到真实镜头/句界/节奏点；没有近点就保留模型时间。
3. **开头 ≠ hook**：第一段仍优先标「开场钩子」；开头可以覆盖 hook 以及其后仍属于开场的片段。
4. **成片连续**：脚本把 `[0, opening_end)` 收成一个镜头（或一组禁止内部切/淡的锁定块）；成片从源片连续取出这一段，或整段一次生成。

## 4. 提示词设计（锁定，必须精心落地）

改 `backend/video_fission/understand/prompts.py` 的 `prompt_video_split`（及解析侧）。这是本任务最重要的部分。允许在不改变下列语义的前提下润色中文，禁止削弱约束或改回「第一段不超过 10 秒即等于开头」。

在「任务」中明确增加：除整片标签与分镜拆分外，必须给出**视频开头区间**。开头是理解结果，不是切分完后倒推出来的时间戳。

必须写入提示词的语义（建议单独成节「视频开头区间」）：

- 开头从 00:00 开始，到「开场故事、画面与节奏」自然收住为止。
- 开头不是 hook。Hook（一级标签「开场钩子」）只负责最前面把滑动停住，通常更短，也不负责把卖点讲完。开头是完整的开场单元：钩子之后若仍在铺处境、人物、情绪或同一镜头/同一节奏里把观众带进正片，这些都还算开头。
- 常见长度大约 10–15 秒，这只是经验范围，不是配额。内容在 8 秒已经转入卖点讲解或场景跳变，就应更短；内容在 16–18 秒才把开场节奏收住，就应更长。禁止为了落在 10 秒或 15 秒整点而切断。
- 禁止硬切：不要在动作做到一半、一句口播说到一半、同一镜头的连续运动/推拉还没停、同一句字幕或同一节奏段落还没结束的地方结束开头。边界应落在镜头或场景切换、一句旁白或台词说完、节奏从开场转入主体（卖点、演示、效果、促销等）的位置。
- 若某个已拆片段会横跨开头结束点：只有当这里本身就是上述那种真实语义转折时，才把开头结束点与该片段边界对齐；否则把开头延长到该片段结束，不要为了「卡在 15 秒」再切一刀。
- 短片（总时长大约不超过 12 秒，或全片都是同一开场节奏）可以把开头标到全片结束，并在 reason 里说明。
- 先根据画面、字幕和语音完整理解，再同时给出分镜与开头区间，而不是先按 hook/value/cta 切完再随便填一个 10–15 秒。

JSON 必须增加（时间格式与现有 `start_time` / `end_time` 一致，可用 `MM:SS` 或带一位小数）：

```json
"opening": {
  "start_time": "00:00",
  "end_time": "00:12.4",
  "reason": "用一两句说明为何这里是开场的自然结束：故事说到哪、画面如何转、节奏如何收住。"
}
```

`reason` 必填，须具体，不得只写「约 12 秒」或「按常规开头」。校验清单里增加：是否输出了 opening；开头是否从 00:00 开始；是否把 hook 误写成开头；结束点是否落在真实转折而非整点；reason 是否说清了故事/画面/节奏。

片段规则可微调，但不要删掉「第一段优先开场钩子」。把「第一个片段通常是钩子，不超过 10 秒」改为与开头区分后的表述：钩子段落仍然宜短，且不得与开头区间画等号；单个普通片段时长建议仍可参考 5–15 秒，但属于开头连续块的内容不要为了上限而切开。

## 5. 整合设计（已锁定）

### 5.1 模型结果解析

在现有整片 JSON 解析中读取 `opening`。`start_time` 规范为 0；`end_time` 转为 `end_ms`；缺字段、无法解析或 `end_ms <= 0` 视为模型未给出有效开头，记 warning，不得静默用 10–15 秒补上并称作模型结果。`reason` 保留原文。

### 5.2 本地吸附（模型之后，只一次）

新增纯函数，建议放在 `understand/opening.py`（名称可商榷，职责必须单一），例如 `snap_opening_end(end_ms, *, duration_ms, cuts_ms, silence_ms, window_ms=600) -> int`。

锁定规则：

- 只在模型 `end_ms` 的 ±600ms 内寻找候选（场景切点、转场峰值、静音/句末）。取窗口内最近者。
- 窗口外即使有「更标准」的 10–15 秒切点，也不得采用。
- 没有候选则保留模型时间（只允许做不超过 1 帧的合法化，且不得改变语义）。
- 若窗口内句界与切点冲突：优先不切断一句口播（选句末），但仍必须在 ±600ms 内。
- `opening.start_ms` 永远是 0；`opening.end_ms` 必须满足 `0 < end_ms <= duration_ms`。长片应给主体内容留出时间，但这不能压过模型判断。
- 吸附后若某模型片段边界已落在同一窗口内，允许把 `opening.end_ms` 与该边界对齐。
- 记录 `method`: `model`（已吸附或无需吸附）或 `local_fallback`（仅无模型时）。最终验收只认 `method=model` 的开头。

无 Key / 模型失败：可计算本地暂估（搜索窗约 8–18 秒，优先真实切点与句界，没有切点就不要硬切，短片则为全片），写入时必须 `method=local_fallback`，且前端不得标成已确认的模型开头。默认 `local_ffmpeg` 仍必须跑完全程。

不要把第一刀再强行切在 1.5–3 秒。若本地兜底仍使用 `plan_segments`，第一段边界必须落在真实切点/句界；没有近点则不要发明一刀。这只影响无 Key 兜底切分，不得用来改写模型开头。

### 5.3 Production / 卡片加法

`decomposition` 增加：

```json
"opening": {
  "start_ms": 0,
  "end_ms": 12400,
  "reason": "...",
  "method": "model",
  "segment_ids": ["seg_01", "seg_02"]
}
```

`segment_ids` 为时间范围落在开头内的片段（允许最后一段与 `end_ms` 对齐）。既有 `segments[]` 仍覆盖全片、不重叠。可选同时切出连续源片 `clips/opening.mp4`（`[0, end_ms)`），便于复用和播放；路径必须能被 artifacts 的 `{name:path}` 取到。

对话卡片：不新增卡片类型，不改稳定 id。`video_understanding` 与 `video_segments` 的 payload 加法带上 `opening`（仅 `method=model` 时作为「开头区间」展示；`local_fallback` 若展示必须明确是本地暂估）。

### 5.4 脚本：开头是一个连续镜头

改 `local_script` 以及模型脚本文案/规范化（`normalize` 脚本结果的函数）：

- 脚本增加 `opening`（与 decomposition 对齐的 `start_ms` / `end_ms` / `shot_id`）。
- `[0, opening_end)` 只对应 **一个** shot（建议 id 稳定，如 `shot_opening` 或现有编号的第一镜），`duration_ms = opening_end`。
- 该镜 `action` 要么整段 `reuse`（源为开头连续块，优先 `clips/opening.mp4`，或从源片按 `[0, end_ms)` 一次裁出），要么整段 `generate`（一次生成整段开头，duration 为整个开头）。禁止把开头拆成「hook 生成 + 开头里其余 value 复用」两镜。
- 默认策略：有可用源片时，开头块优先 `reuse`（因为连续性和原片节奏最重要）；用户明确要求全部新生成，或 `replace_plan` 点名重做开头时，整块 `generate`。`replace_plan` 涉及开头内任一原片段时，视为重做整个开头块。
- 开头之后的镜头从 `opening_end` 开始，仍按现有 hook/value/cta 之外的片段与 replace 规则处理。不要重复使用已被折进开头块的源时间。
- 模型脚本若仍按旧片段拆镜，规范化阶段必须合并开头块，而不是原样采用。

意图骨架里仍可保留 hook 文案（一句话钩子），但这是文案，不是把媒体再切短。

### 5.5 成片：开头内部禁止硬切和淡化

`_stage_generate` / `_stage_compose`：

- 开头 shot 只产出一个媒体文件，时长与 `opening.end_ms` 一致（允许既有时长容差，不得在块内再拼按 hook/value 切开的两段）。
- 开头块内部不得 `apply_edge_fades`，也不得插入转场。现有镜头交界淡化只允许出现在「开头块结束 ↔ 后续镜头」以及后续镜头之间。
- 复用时按开头区间一次裁切，不要先裁 hook 再裁下一段再拼接。
- 硬烧字幕、音画对齐仍以该连续块的时间轴为准。

### 5.6 前端

在理解卡和片段卡上标出开头区间，例如「开头 0:00–0:12」，并展示 `reason`（可折叠或次要文本）。片段时间轴用范围高亮 `[0, opening_end)`，不要只靠把第一段改名为开头。无模型开头时不假装已识别；本地暂估若显示需有区别。样式与现有卡片一致，入口仍在对话消息列表。
