# Video References

这是一个共享参考库，服务于两个阶段：

- `creative-intent-script-skeleton`：只用首屏骨架与注意项，帮助确定创作意图和叙事骨架。
- `universal-ugc-video-script-generation`：在骨架确认后读取完整参考脚本，填充镜头级内容。

不要把参考脚本当成当前产品的素材，也不要把商品、人物、场景或未经证实的功效直接迁移到新任务中。参考的是看点组织、冲突建立、物理动作、节奏和爽感兑现方式。

## 文件结构

所有路径都相对于本 Skill 根目录：

```text
references/index.md
references/<品类>/<序号_风格_时长_口播形式_动作梗概>.md
```

`references/index.md` 包含 2 个品类的 13 篇全量目录。单篇脚本固定为三段：

1. 第一个 `---` 之前：首行脚本骨架。
2. 两个 `---` 之间：人物、商品、物理连续性和画面注意项。
3. 第二个 `---` 之后：全局五要素和 `Lens 1 ~ Lens N` 完整分镜。

## 两阶段检索契约

### 1. 意图与骨架阶段

当调用方是 `creative-intent-script-skeleton`：

1. 先读取 `references/index.md`，或直接用文件名检索 `references/`。
2. 根据商品的同义卖点、目标国家、风格、时长、口播形式和核心动作，优先选定 3 篇同品类候选和 1 篇跨品类候选；同品类不足 3 篇时用另一品类补齐。
3. 每篇只读取首行骨架和第二个 `---` 之前的注意项；这个阶段不需要加载完整分镜。
4. 输出实际使用的文件路径，并说明每篇提供的核心结构，而不是只报告“已参考”。

### 2. 完整脚本阶段

当调用方是 `universal-ugc-video-script-generation`：

1. 从已确认的骨架和调用方指定的检索结果中，选择至少 3 篇结构最匹配的脚本。
2. 每篇必须从头到尾完整读取，核对全局五要素、时间轴、动作连续性和声音设计。
3. 可以借鉴多个完整脚本的结构关系，但禁止把不同脚本的零散镜头切片拼成“伪参考”。
4. 新脚本必须围绕当前商品和当前创作说明重新设计，不得复刻参考中的品牌、真人身份、产品外观或虚假证明。

## 检索与排序

候选脚本按以下顺序比较：

1. 当前商品与参考商品的功能机制是否相似。
2. 用户想要的核心视觉证据是否相似。
3. 开场痛点和最终爽感是否相似。
4. 目标市场、时长和口播形式是否兼容。
5. 制作成本、人物数量和场景数量是否可执行。

如果同品类候选不足，保留两到三个关键维度从另一个品类补齐。例如“出风口破雪开圆”可以迁移到“风炮劈水见底”的物理前后对比结构。必须说明这是结构迁移，不是产品类比。

## 文件名检索

优先用文件名完成粗筛，再读取正文：

```bash
rg --files references/<品类>
rg -n '<关键词1>|<关键词2>|<目标国家>|<时长>' references/index.md
```

文件名中的 `实测`、`标准`、`剧情`、`促单`、`展示`、`产品故事` 表示内容形态；`有口播` 和 `无口播` 表示声音组织方式，不应混用。

## 质量检查

返回检索结果前确认：

- 至少包含调用方要求的同品类和跨品类覆盖。
- 路径真实存在，没有凭目录名猜测文件。
- 说明的是可迁移结构，不是把参考文案换几个词。
- 没有把参考中的功效、数据、人物关系或商品外观当作当前商品事实。
- 骨架阶段没有提前展开完整分镜，完整脚本阶段没有只看首行就声称已完整参考。
