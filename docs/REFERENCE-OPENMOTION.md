# 借鉴 OpenMotion 的参考说明

更新：2026-11-18 17:23 Asia/Shanghai
来源：[OpenMotion](https://github.com/nexu-io/openmotion)（工作区副本：`/workspace/openmotion`，查阅时 HEAD 为 `d968896`）
适用范围：`video-fission` 对话内视频创作流水线。本文是借鉴说明，不是新的开发任务书，也不修改已锁定任务书。

前序锁定文档仍然有效：`docs/TASKS-VIDEO-PIPELINE.md`、`docs/TASKS-CHAT-NATIVE-PRODUCTION.md`、`docs/TASKS-SLOT-UNDERSTANDING.md`、`docs/TASKS-OPENING-SPAN.md`、`docs/TASKS-LANDING-CREATIVE-AUDIO.md`。

## 1. 结论

OpenMotion 值得借鉴的不是它的 HTML/CSS/JS 动效工程，也不是 Hyperframes Studio，而是四条创作原则：

1. 把参考片里必须保住的东西写成可复用规范，让每次出脚本、再生成都对准同一条参考时间轴。
2. 把品牌/卖点（含落地页）和运动语言分开，换文案时不重做节奏。
3. 成片后保留同一条任务上的可编辑工程和版本，跟进是改它，而不是推倒重来。
4. 导出只做技术校验；视觉是否像参考要单独看。无 Key 的本地路径不得写成「已还原」。

`openmotion-recreate` 还提供比这四条更细的交互、图层和校对设计，见第 9 节。核心不是把参考片整段铺进时间线，而是先读完整参考、判断用户要「复刻给我们」还是「只要这个感觉」，再建成可继续改的工程；默认只做一次有限校对，深挖视觉还原要用户明确提出。

本项目继续走「拆解参考 → 出 3 个脚本供选择 → 生成镜头并合成」的路径，不改成 OpenMotion 那样的代码化时间轴。

## 2. 不搬什么

- 不接入 OpenMotion 的 Studio、MCP、Hyperframes 渲染，也不把成片主路径改成 HTML 导出 MP4。
- 不把 Motion.md / Motion Package 当作本仓库的强制文件格式或自动导入器。
- 不把官网宣传的还原度、模板数量或模型名单写进本项目验收标准。
- 不推翻已锁定的开头连续块、三脚本暂停选择、人声/BGM 分离和合成时硬烧字幕。
- 不搬纹理粒子重建、HTML 渲染助手或他们的测量 CLI；那是 OpenMotion 自己的动效引擎。
- 不改成「没有单独的理解阶段、观察直接进入编写」。本项目继续保留理解/分解和开头连续块。

## 3. 可复用的参考约束

对应 OpenMotion 的 Motion.md：一份说明「什么必须保持、什么可以替换」的规范。在本项目里，它应对准已经锁定的参考时间轴和开头连续块，成为 intent、script、generate、compose 的共同约束。

建议一份参考约束至少包含下列分节。可由理解/分解阶段生成，随生产任务保存，三次出脚本和再生成都读取同一份，而不是各写各的。

### 3.1 开头连续块

- 开头是内容驱动的连续区间 `[0, opening_end)`，通常约 10–15 秒，但不得用 3/10/15 秒硬切。
- 最终开头应以多模态视觉模型结果为准；本地吸附只允许在模型结果之后做一次。无 Key 或模型失败时记 `method=local_fallback`，不得标成已确认的模型开头。
- 脚本和成片把该区间收成一个连续镜头（`shot_opening`）：整块复用或整块生成，内部不得硬切或做边缘淡化。淡化只出现在开头与正文交界。
- `replace_plan` 触及开头内任一段时，应重做整个开头块。

### 3.2 镜头节奏与时间轴

- 参考片的镜头边界、时长、持有、转场点和声画锚点是运动语言，默认锁住。
- 每次生成 3 个创意脚本时，三个候选必须共用同一条参考时间轴和同一个开头连续块，只允许角度、口播、画面描述和花字不同。
- 「再出 3 个脚本」仍然锁这条时间轴，不得因为换了卖点文案就重切镜头。
- 「再生成视频」沿用已选用脚本所绑定的时间轴，而不是另起一条节奏。

### 3.3 口播

- 生成阶段必须有口播，且口播应与选用脚本的 `voiceover` 对齐。
- 参考片应分离人声和背景音乐，分别作为参考音频传给视频生成模型；合成时只混分离后的 BGM，不得把整段混合音轨再铺一层。
- 模型返回无声时，优先 TTS，其次才是时间对齐的参考人声。无音轨或占位茎不得当成已有口播，也不得写入静音轨充数。
- 换文案时可以改口播内容，但口播的时间位置应仍落在锁定的镜头节奏上；超长口播应改写或拆句，而不是压缩到不可读。

### 3.4 字幕

- 视频模型不得在画面里烧字幕、标题、花字或说明文字。字幕只在合成阶段硬烧。
- 字幕样式和位置应尽量跟随参考片（有软字幕轨则读取，否则再检测烧字区域）。读不到时使用安全默认样式，并明确 `method=default_safe`、`aligned=false`，不得声称「已按参考对齐」。
- 字幕时间轴跟随口播和镜头节奏，不另做一套与参考脱节的字幕时长。

### 3.5 不变量与可替换项

| 默认保持（运动语言） | 默认可替换（品牌与文案） |
| --- | --- |
| 开头连续块 `[0, opening_end)` | 落地页卖点、利益点、人群、承诺 |
| 参考时间轴、镜头时长、转场点 | 创意角度、口播原文、花字 |
| 口播与字幕的时间位置 | 品牌名、产品名、视觉提示词 |
| 分离后的 BGM 使用方式 | 选用哪一个脚本候选 |
| 字幕样式的参考对齐目标 | 跟进修改中的文案调整 |

## 4. 品牌 / 卖点与运动语言分离

落地页解析得到的产品、卖点、利益点、人群、承诺，属于品牌和文案层。它们进入 intent / script / generate 的提示词，用来改「说什么、卖什么」，不用来重做节奏。

实践要求：

- 没有落地页地址时，流水线不得失败；解析失败或部分成功时，要如实记录 `parse_status`，不得写成已完整分析。
- 用户调整卖点或文案后「再出 3 个脚本」，三个候选仍锁同一条参考时间轴和开头连续块。
- 已选用脚本后再生成视频，只重做画面和合成，不重新切时间轴。
- 「用第 2 个」是选择候选，不是重出脚本。

这一分离对应 OpenMotion「同一套运动语言、换故事和品牌」的做法，但落在本项目已有的 `landing_page`、`script_candidates` 和 `resume_from=script|generate` 上，不必引入新的卡片类型。

## 5. 同一条任务上的可编辑工程与版本

跟进默认作用在当前生产任务上，而不是新建一条从 ingest 开始的任务。

建议保留并在跟进中继续使用的产物包括：参考约束、理解/分解结果、开头区间、落地页卖点、三个脚本候选与 `selected_script_id`、分离后的人声/BGM、字幕样式、各阶段成片与中间文件。

跟进规则：

- 等待选择或讨论文案/卖点/脚本时，从脚本阶段再出 3 个候选。
- 已经选用脚本且用户要求改画面或再生成时，从 generate 继续。
- 版本回退应生成新的内容版本，并保留之后的历史，而不是覆盖丢失。
- 用户只说「不满意」时，一次最多问三个选择题（例如改文案、节奏还是画面），然后改同一条任务，而不是另开一条。
- 判断不准会改整条片子时，最多问一轮，并给出「你来定」。

OpenMotion 的版本列表与恢复思路可以后续借鉴；在本说明中只作为原则，不新增未锁定的 API 契约。

## 6. 校验分层

技术校验和视觉还原必须分开记录，任何一项通过都不能代替另一项。

**技术校验（导出/合成即可做，也是当前无 Key 路径要写清的范围）：**

- 成片容器、编码、分辨率和时长与脚本时间轴一致。
- 脚本阶段恰好 3 个候选并暂停，选用后再进入 generate。
- 人声/BGM 是两条不同的轨；合成只混分离 BGM。
- 有口播，且未把静音占位当成口播。
- 字幕在合成阶段硬烧；读不到参考样式时使用安全默认，并标明未对齐。
- 开头连续块内部无硬切。

**视觉还原（单独看，需要有效的视觉模型或人工审看）：**

- 默认只需抽最多 4 个对应时刻做一次对照：构图、关键运动、最难转场、结尾。明确缺陷只改一轮。
- 量化打分和逐帧复盘留到用户明确要求时再做，不作为默认验收。
- 开头区间是否与参考的叙事/画面/节奏连续。
- 镜头运动、转场和持有是否像参考。
- 口播、画面和字幕是否卡在参考节奏上。
- 品牌和卖点是否替换到位，同时没有破坏运动语言。

禁止把下列结果写成「已还原参考」或「已按参考对齐」：

- `local_ffmpeg` / 无 Key 的本地生成或复用
- `method=local_fallback` 的开头
- `method=local_ms` 或占位茎的音频分离
- `method=default_safe` 且 `aligned=false` 的字幕样式
- 未实际调用视频生成模型的功能跑通

本轮用户要求以功能实现为准、不做完整链路验证、环境中也不走视频生成模型。因此技术校验可以通过，视觉还原仍应标记为未验收。

## 7. 建议的文档与产物位置

在启动新的开发任务之前，先把上述约束落成任务内的一份参考说明，而不是先接入 OpenMotion 运行时。建议位置：

- 本说明保持在 `docs/REFERENCE-OPENMOTION.md`，作为项目级原则。
- 单次生产任务可将实例化约束存在该任务目录或生产记录中（例如 `reference_constraints`），供脚本候选和再生成共用。
- 若要写成可独立阅读的 Markdown，分节与第 3 节保持一致：开头连续块、镜头节奏、口播、字幕、不变量/可替换项、校验记录。

真正改代码、补字段或补验收项时，另开任务书，并与已锁定文档对齐后再实施。

## 9. 从 openmotion-recreate 补入的设计

来源：工作区副本 `skills/openmotion-recreate/`（查阅时与文首同一 HEAD `d968896`）。本节比第 1 节的四条原则更细，仍是借鉴说明，不新增未锁定的 API，也不在本文中启动实施。

`openmotion-recreate` 的核心不是把参考片整段铺进时间线，而是先读完整参考，判断用户要「复刻给我们」还是「只要这个感觉」，再建成可继续改的工程。默认只做一次有限校对；深挖视觉还原要用户明确提出。

### 9.1 先读材料，再判断意图

- 先读工作区里已有的品牌和卖点，再读参考片。
- 用户只给一条裸链接，而工作区里已有产品材料时，通常就是「按这个样子给我们做」，不必再把意图问成开放题。
- 请求没提到的部分默认保持原片，不要自己加装饰，也不要按节拍重切镜头。
- 判断不准、这一步可能会改整条片子时，最多问一轮，并给出「你来定」。
- 用户只说「不满意」时，一次最多问三个选择题，然后改同一条任务，而不是另开一条或推倒重来。

### 9.2 可编辑层与生成镜头的边界

- 文字、Logo、字幕、界面应作为可编辑层，不要烧进模型画面。本项目里，字幕和花字仍在合成阶段硬烧，以便后续改文案时不必重做镜头。
- 生成镜头只对齐角色、构图、运动和时长，不追求像素级还原，也不追求与参考里真人身份一致。
- 参考片有声音，成片就要有声音。
- 口播要换品牌或产品时，尽量保持原片的语言、语气和时间位置；超长口播应改写或拆句，而不是把时长压到不可读。
- 未得到生成许可时，不要为了跑通流水线就删掉或替换旁白。
- 如果只是改年份、一句文案或 Logo，应在原片上局部覆盖，而不是整条重做。

### 9.3 连续帧阅读与有限校对

- 读参考要用连续帧看切入、停留和切出，不能用一秒一帧的概览当作运动证据。
- 镜头检测结果也要对照相邻帧核对，避免把硬切误抹平。本项目仍保留理解/分解阶段和开头连续块，不改成「观察完直接编写」。
- 默认交付只需抽最多 4 个对应时刻做一次对照：构图、关键运动、最难转场、结尾。明确缺陷只改一轮。
- 量化打分和逐帧复盘留到用户明确要求，不作为默认验收。
- 交接时用一两句话说清改了什么、做了哪些假设、用户会看到哪些限制。绝不把没做到的还原写成已经做到。无 Key 的本地路径、`local_fallback` 开头、占位茎和未对齐的默认字幕，同样不得写成「已还原」。

### 9.4 明确不搬的部分

纹理粒子重建、HTML 渲染助手和他们的测量 CLI，属于 OpenMotion 自己的动效引擎，不必搬到本项目。它「没有单独的理解阶段、观察直接进入编写」也不适合我们：理解/分解和开头连续块应继续保留。
