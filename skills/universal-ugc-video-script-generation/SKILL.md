# Universal UGC Video Script Generation

把一个已确认的创作骨架填充成能直接进入片段复刻、视频生成和 ffmpeg 合成的制作脚本。此 Skill 负责“写清楚怎么剪、怎么生成、声音怎么接”，不负责声称已经生成或渲染了视频。

## 前置条件

开始前必须具备：

- 已确认的一行骨架和 Hook / Value / CTA 结构。
- 当前商品真实事实、目标市场、画幅、总时长和 CTA。
- 参考视频的切片结果，至少包含每个原片片段的起止时间、内容和声音状态。
- 哪些片段允许直接复用，哪些必须复刻或新生成。

缺少会改变镜头结构的输入时，先回到 `creative-intent-script-skeleton`，不要用编造内容补齐。

## 读取完整参考

使用 `$video-references` 并遵守其“完整脚本阶段”：

1. 根据已确认骨架和含义识别到的商品品类，选择至少 3 篇结构最匹配的脚本。
2. 优先 2-3 篇同品类，再加至少 1 篇跨品类动作或节奏参考。
3. 每篇从头到尾完整读取，核对时间轴、动作连续性、镜头关系、对白和音效。
4. 记录真实路径和各自借鉴的完整结构。禁止跨脚本取零散片段后拼成未完整阅读的“参考”。

参考只用于结构启发。当前商品、人物、场景、证据和台词必须重新创作。

## 生成原则

- 每个镜头只承担一个主要信息或动作变化。
- 先给结果预期，再给证据，最后用同一视觉母题收束。
- 动作必须符合物理连续性：起点、施力、变化、结果和反应都能在时间轴上看见。
- 同一商品在多镜头中保持外观、颜色、配件、人物服装和场景一致。
- 口播、字幕和画面表达同一信息，不让字幕承诺画面没有展示的功能。
- 目标市场需要当地语言时，屏幕上只保留必要的本地化文字；不出现无关中文。
- 不使用无法由真实素材证明的测试数据、认证、医疗功效或用户评价。

## 脚本结构

### 全局五要素

```markdown
**Duration:** [秒数]
**Style:** [画面真实性、拍摄方式、市场风格、节奏]
**Scene:** [场景、时间、光线、关键环境状态]
**Cast:** [人物年龄、市场族裔、外观、服装、真实肤质要求]
**Product Reference:** [商品外观、颜色、配件、状态和不可误判特征]
```

### 镜头级分镜

每个 Lens 必须包含：

- `[开始-结束]`：使用秒级时间轴。
- `Visual`：观众具体看到什么。
- `Frame`：构图、景别和画面中必须同框的主体。
- `Action`：按子时间点描述动作变化，而不只是情绪。
- `Camera`：焦段、机位、运动方式和焦点变化。
- `Facial Expression`：可执行的面部反应。
- `Audio & Dialogue`：对白语言、说话人和声音层级。
- `Spoken Line`：完整原句；无口播时明确写“无”。
- `Sound Effects`：与画面事件卡点的声音。

## 片段制作清单

分镜之后必须给出机器可读的片段计划。使用以下 JSON 结构；没有的信息写 `null` 或在 `notes` 说明，不要编造：

```json
{
  "total_duration": 15,
  "aspect_ratio": "9:16",
  "segments": [
    {
      "id": "seg-01",
      "narrative_role": "hook",
      "start": 0,
      "end": 3,
      "production_mode": "replicate",
      "source_ref": {
        "clip_id": "source-02",
        "start": 4.5,
        "end": 7.5
      },
      "visual_prompt": "可交给视频模型的单镜头描述",
      "negative_constraints": ["商品外观锁定", "不出现无关中文"],
      "transition_in": "hard-cut",
      "transition_out": "match-cut",
      "audio_strategy": {
        "source_audio": false,
        "dialogue": "generated",
        "music": "reuse-source",
        "sfx": ["metal-impact"]
      },
      "subtitle": "屏幕字幕原文",
      "notes": null
    }
  ]
}
```

`production_mode` 只使用 `reuse`、`replicate`、`generate` 或 `hybrid`。对 `reuse` 片段必须写明原片 `clip_id` 和精确起止时间；对生成或复刻片段，提示词必须包含主体动作、场景、镜头、商品一致性约束和禁止项。

## 声音与合成方案

即使当前阶段不执行音轨处理，也要在片段计划中说明后续策略：

- 对白、音乐和音效分轨记录，避免直接依赖原片混合音轨。
- 跨越口播边界时，优先切断原片对白，保留可循环的音乐或用新音乐重建节奏。
- 复用片段只在说话连续、画面动作连续且授权允许时保留原声。
- 新生成片段若没有原生声音，后续通过 TTS 或配音补口播，字幕以最终配音为准。
- 转场优先 hard-cut、match-cut、动作遮挡和物理转场；不用花哨转场掩盖动作不连续。
- 每个片段明确画幅、帧率和分辨率，合成阶段统一后再拼接。

## 交付

默认交付：

1. 全局五要素。
2. 完整 Lens 分镜。
3. JSON 片段制作清单。
4. 原片复用、复刻、生成三类片段汇总。
5. 口播、音乐、音效和字幕处理说明。
6. 参考脚本路径及借鉴的完整结构。

如果用户只要求脚本，到此停止；不要声称片段、配音或成片已经生成。

## 质量检查

交付前逐项检查：

- Hook、Value、CTA 都有明确时间范围和镜头证据。
- 所有动作可以从时间轴推断出来，不依赖“增强代入感”等空话。
- 总时长与各片段首尾连续，没有重叠或空档。
- 每个复用片段都指向真实原片区间；没有原片区间时不得标为 `reuse`。
- 商品、人物和场景在镜头间保持一致。
- 广告宣称均有用户提供的事实或原片证据支撑。
- JSON 片段清单与自然语言分镜一致。
